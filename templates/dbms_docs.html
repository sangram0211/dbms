Key Cardinality Relationships:
  • USERS to EXPENSES (1 : N): One user can record zero or many expenses. Every expense belongs to exactly one user.
  • CATEGORIES to EXPENSES (1 : N): One category can classify multiple expenses. Foreign Key has ON DELETE RESTRICT to prevent orphan records.
  • PAYMENT_METHODS to EXPENSES (1 : N): Every expense references a validated payment method.
  • USERS to BUDGETS (1 : N): A user sets monthly budget limits per category with a UNIQUE(user_id, category_id, month, year) composite constraint.
  • EXPENSES to EXPENSE_AUDIT_LOGS (1 : N): Automatic audit trail captured through database triggers.
Relational Schema & Normalization (3NF)
Relational Notation:
1. USERS (user_id, username, email, password_hash, full_name, currency, created_at)
2. CATEGORIES (category_id, user_id, name, icon, color, created_at)
3. PAYMENT_METHODS (payment_method_id, method_name, icon)
4. EXPENSES (expense_id, user_id, category_id, payment_method_id, amount, expense_date, description, created_at)
5. BUDGETS (budget_id, user_id, category_id, month, year, monthly_limit, created_at)
6. EXPENSE_AUDIT_LOGS (log_id, expense_id, user_id, action, old_amount, new_amount, action_timestamp, details)
Normalization Justification:

Every table has an atomic primary key (`user_id`, `category_id`, etc.). All attributes hold single, indivisible (atomic) values. No repeating groups or comma-separated lists (e.g. categories and payment methods are separated into distinct relations).

The schema satisfies 1NF. Every non-prime attribute is fully functionally dependent on the entire primary key. In relations with composite unique constraints (such as `budgets`), the attribute `monthly_limit` depends on the full tuple `(user_id, category_id, month, year)`, eliminating partial dependency.

The schema satisfies 2NF. There are no transitive dependencies (`X -> Y -> Z`). For instance, `expenses` stores `category_id` rather than category name, color, or icon. Category attributes depend strictly on `category_id`.
Database Triggers & Views Code
1. Database Trigger: After Expense Insert
DELIMITER $$
CREATE TRIGGER `trg_after_expense_insert`
AFTER INSERT ON `expenses`
FOR EACH ROW
BEGIN
    INSERT INTO `expense_audit_logs` (
        `expense_id`, `user_id`, `action`, `old_amount`, `new_amount`, `details`
    ) VALUES (
        NEW.`expense_id`, NEW.`user_id`, 'INSERT', NULL, NEW.`amount`, 
        CONCAT('Created expense: ', NEW.`description`)
    );
END$$
DELIMITER ;
2. Database View: Monthly Category Summary
CREATE OR REPLACE VIEW `vw_monthly_category_summary` AS
SELECT 
    e.`user_id`,
    YEAR(e.`expense_date`) AS `expense_year`,
    MONTH(e.`expense_date`) AS `expense_month`,
    c.`category_id`,
    c.`name` AS `category_name`,
    c.`color` AS `category_color`,
    COUNT(e.`expense_id`) AS `total_transactions`,
    SUM(e.`amount`) AS `total_spent`
FROM `expenses` e
JOIN `categories` c ON e.`category_id` = c.`category_id`
GROUP BY e.`user_id`, YEAR(e.`expense_date`), MONTH(e.`expense_date`), c.`category_id`, c.`name`, c.`color`;
3. Database View: Budget Status vs Actual Spending
CREATE OR REPLACE VIEW `vw_budget_status` AS
SELECT 
    b.`budget_id`,
    b.`user_id`,
    b.`category_id`,
    c.`name` AS `category_name`,
    c.`color` AS `category_color`,
    b.`month`,
    b.`year`,
    b.`monthly_limit`,
    COALESCE(SUM(e.`amount`), 0.00) AS `spent_amount`,
    (b.`monthly_limit` - COALESCE(SUM(e.`amount`), 0.00)) AS `remaining_amount`,
    ROUND((COALESCE(SUM(e.`amount`), 0.00) / b.`monthly_limit`) * 100, 2) AS `percentage_used`
FROM `budgets` b
JOIN `categories` c ON b.`category_id` = c.`category_id`
LEFT JOIN `expenses` e ON e.`user_id` = b.`user_id` 
    AND e.`category_id` = b.`category_id`
    AND MONTH(e.`expense_date`) = b.`month`
    AND YEAR(e.`expense_date`) = b.`year`
GROUP BY b.`budget_id`, b.`user_id`, b.`category_id`, c.`name`, c.`color`, b.`month`, b.`year`, b.`monthly_limit`;
MySQL Setup & Submission Guide
How to run with MySQL (XAMPP / MySQL Workbench / Terminal):
  1. Start MySQL: If using XAMPP or MAMP, start the MySQL service. If using Homebrew/standalone MySQL, run mysql.server start.
  2. Import the SQL Schema:
    mysql -u root -p < database/schema.sql
    Or open phpMyAdmin (http://localhost/phpmyadmin), click Import, choose database/schema.sql, and click Go.
  3. Configure Environment: Check the .env file in the project root:
    DB_ENGINE=mysql
    DB_HOST=127.0.0.1
    DB_USER=root
    DB_PASSWORD=
    DB_NAME=expense_tracker_db
  4. Run the Web App:
    ./venv/bin/python3 app.py
    Visit http://127.0.0.1:5000 in your web browser.
Dual-Engine Compatibility: If MySQL is not running on your computer, the application automatically falls back to the embedded SQLite database with the exact same relational triggers, views, and integrity rules, so you can test and present without connection failures!
